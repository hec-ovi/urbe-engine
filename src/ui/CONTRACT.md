# CONTRACT: ui (engine inner box)

Purpose: every screen the player sees over the game, as plain DOM components that are handed values and report intents through callbacks; no game logic, no scene code.

Layout: `views/` are full panels and the overlays that assemble them, `widgets/` are the small HUD pieces and popups, `components/` are shared primitives and every stylesheet. Each class exposes `element` (its root node); inputs are `set*` methods or constructor props, outputs are constructor callbacks.

## GameView (views/GameView.js)
The whole game overlay. `mount( parent )` appends it.
- props (all optional): `onResume()`, `onSave()`, `onCloseDialog()`, `onSend( text )`, `onOpen( name )`, `onClose()`, `onLeave()`, `onSettingChange({ key, value })`, `onHangUp()`, `onSummaryClose()`, `onTransitSelect(value)`, `onTransitCancel()`, `onQuestSelect(questId)`, `onQuestTrack(questId, stepId?)`, `onQuestWait(questId, stepId)`, `onSummaryOpen()`, `onDialogueChoice(value)`, `onDialogueTopic(value)`, `onDialogueAction(id)`, `onDialogueRetry()`, `onDialogueJournal()`, `onDialogueVoice(on)`, `menu` (the `MainMenuView` callbacks below)
- methods: `open( name )`, `close()`, `toggle( name )` with name one of `QUESTS`, `MAP`, `INVENTORY`, `CODEX`, `SETTINGS`, `CONTROLS`; `setPaused( bool )` shows the pause menu, under any panel, chat or summary opened over it, and the tab bar is up only while a panel is open; `setPointerFree( bool )` shows the line (`free` in the [game menu](views/game-menu.json)) saying how to take the pointer back while the world plays on; `setDetails( bool )` shows or hides the developer readouts (`readout` and `stats`) together; `step( text, progress? )`, `ready()`, `fail( message )` drive the loading surface (`LoadingScreen`, still `.hud-loading` with its `.hud-loading-step` line and `.hud-loading-error`), `progress` being LoadProgress's record `{ label, step, done, total, part }`; `setLoadingPlace( name )` names the game under its crystal
- `setObjective({ title, objective, state: 'active' | 'unavailable' | 'done', note?, place } | null)` updates the persistent gameplay objective; null or an object with no title and no objective hides it. `note` explains an unavailable objective. `place` is null or `{ name, distanceMeters?, window? }`, shown as a line under the objective ("Oxide Filter, 120 m") and, while `window: { label, startMin, endMin }` is given, the hour it opens ("Opens during the slow hour, 18:00 to 23:00")
- front-door methods: `showMainMenu()`, `hideMainMenu()`, `setLibrary(data)`, `setCreationState(data)`. While the menu is shown, gameplay UI is inert and hidden from assistive technology.
- children the game feeds directly: `clock`, `prompt`, `shortcuts`, `inspection`, `readout`, `stats`, `objective`, `minimap`, `pause`, `free`, `avatar`, `call`, `toast`, `dialog` (ChatPanel), `summary`, `transit`, `map`, `inventory`, `quests`, `codex`, `settings`, `controls`, `tabs`, `panels`, `mainMenu`

## MainMenuView (views/MainMenuView.js)
The full-screen front door uses the studio game_main composition: Fracture identity and navigation on the left, scrollable saved-session dossiers or a creation card on the right. The architectural drawing is decorative; all save, city, location, inventory and objective values come from the caller. It owns display and selection state only. Storage, generation and game launch remain caller responsibilities.
- callbacks (all optional): `onContinue(gameId)`, `onSave(gameId)`, `onLoad(file)`, `onExportCity(cityId)`, `onGenerateCity(input)`, `onGenerateInstances(input)`, `onGenerateQuests(input)`, `onCreateGame(input)`
- methods: `show()`, `hide()`, `openLibrary('games' | 'cities')`, `createNew()`, `createFromCity(city)`, `setLibrary(data)`, `setCreationState(data)`. `show()` focuses the first enabled menu action; the open directory or creation surface is exposed as the current action.
- `setLibrary({ games, cities })`: both arrays are optional. A game may provide `{ id, name, cityName, theme, playable, mainSteps, sideJobs, interiors, location, position: [x,y,z], activeQuest: { title, objective }, inventory, locations }`. A city may provide `{ id, name, seed, size, status, buildings, interiorCount, districts, summary, availableBuildings }`.
- absent callbacks disable their corresponding control. The menu says when loading is not connected, and each creation stage says when its generator is not connected.
- `onLoad(file)` receives the browser `File` selected by the player. The input accepts JSON game files and clears after every selection.

## GameLibraryView (views/GameLibraryView.js)
The two local directories rendered by the front door.
- methods: `setLibrary({ games, cities })`, `showDirectory('games' | 'cities')`
- `mostRecentGame` returns the first playable game, or null
- game cards show current location and exact position, active quest and objective, recent locations, inventory and content counts
- city cards show generation identity and counts, then report setup or export intent through the callbacks supplied by `MainMenuView`

## NewGameView (views/NewGameView.js)
The creation surface reads field layouts and labels from [creation-layout.json](views/creation-layout.json). Its input [schema](views/creation-layout.schema.json) supports select and number fields, defaults, bounds and options. Shared `CreationForm` uses `SettingField` widgets. Optional stages stay locked until their inputs are ready.
- Stage 1, City: reports `onGenerateCity({ size })`, where size is `small`, `medium` or `large` (displayed as Big). The only field is City size, followed by Next.
- Stage 2, Interiors: reports `onGenerateInstances({ cityId, mode, count, buildingIds })`. Automatic mode defaults to 9 and accepts 9 through 24, reserving seven main-story locations and two unique side-job locations. Manual mode preserves explicit selection and requires 1 through 24 eligible buildings.
- Stage 3, Story and jobs: reports `onGenerateQuests({ cityId, interiorIds, mainBrief, sideJobs })`. Side jobs is 0 through 3 and defaults to 3. The built-in story sends an empty main brief.
- Stage 4, Playable game: reports `onCreateGame({ cityId, interiorIds, questId })` for a completed story. Play without quests is available after City and Interiors; it sends `questId: null` and the completed interior ids, or an empty array.
- methods: `reset()`, `beginWithCity(city)`, `setCreationState(update)`, `open(step)`
- `setCreationState` accepts any supplied part of `{ city, instances, quests, game, busy, error }`. The caller owns the artifacts and uses `busy` with one of `city`, `instances`, `quests`, `game` to lock duplicate actions.
- stage progress is a polite live status; the active pane exposes `aria-busy` while its caller action runs.

## PanelHost (views/PanelHost.js)
One panel over the game at a time.
- props: `views: { NAME: view }`, `onOpen( name )`, `onClose()`
- methods: `open( name )`, `close()`, `toggle( name )`; `current` is the open name or null
- a view is `{ element, shown?() }`; `shown` runs once the view is on screen
- Escape closes while a panel is open; opening one closes the one before
- the open view is an accessible dialog, receives focus, and becomes inert immediately when closed; focus returns to the outside control that opened it when that control remains visible

## Views (one full panel each; every one takes `onClose()`)
- **Map3DView** (the MAP panel): `setWorld({ bounds, buildings: [{ ring: [[x,z]], height }], ground: [{ surface, polygon: [[x,z]] }], transit: { routes: [{ id, kind, path: [[x,y,z]] }], places: [{ id, refId, kind, point: [x,y,z] }] } })` raises every building, lays the ground cover and draws every generated bus, train and subway route at its published height with its stops or street entrances; `kind` is `bus`, `train` or `subway`. `setVenues([{ point: { x, z }, open }])`, `setRoute({ path: [[x,z]], label } | null)`, `setPlayer( position, heading )`, `centre()`; drag turns, wheel zooms, the frame renders only on a change; `shown()` creates the WebGL renderer sized to the stage.
- **MinimapView** (HUD corner, always on): `setMap({ bounds, roads: [{ path: [[x,z]], width }], blocks: [[[x,z]]], transit: { routes: [{ id, kind, path: [[x,z]] }], places: [{ id, refId, kind, point: [x,z] }] } })` bakes the city and generated transit once; `setVenues( venues )`, `setRoute({ path: [[x,z]], label } | null)`, `update( position, heading )` each frame, `toggle()`, `setVisible( bool )`. Heading is camera yaw in radians, forward `[-sin(heading), -cos(heading)]`. Forward stays at the top; city, venues and routes share that rotation. The player stays centered and points up, while N marks world north (-Z). Its studio frame opens MAP through optional `onOpen()`, and its footer reflects the supplied route label. Size, scale and labels come from [layout](views/minimap-layout.json), [schema](views/minimap-layout.schema.json).
- **InventoryView**: `setItems([{ id, name, kind, description, place }])` in slot order over 30 slots, `select( index )` (-1 clears); clicking a slot selects it, exposes the pressed state, and shows its detail
- **QuestsView**: props `onClose()`, `onSelect(questId)` for inspection, and `onTrack(questId, stepId?)` for explicit navigation and `onWait(questId, stepId)` for a timed objective’s explicit wait. `setQuests(...)`, `select(id)` and `setTrackedQuest(id, stepId?)` keep inspection and following separate. Current steps show active/locked/done/cancelled state, place, NPC, availability reason and hours. History is collapsible, and a quest's optional `prologue` reads again in a folded Prologue section. Labels come from [quests-layout.json](views/quests-layout.json), [schema](views/quests-layout.schema.json). Active terminal alternatives show OR, their stakes and authored commitment, with a separate Follow this lead action. A current time-gated step can carry `wait:{timeMin,label}` and exposes Wait until that opening. Tracking does not accept a dialogue decision; a temporarily unavailable lead can remain followed while its reason is visible.
- **CodexView**: `setEntries([{ id, title, category, text }])` grouped by category, `select( id )`; the selected row exposes its pressed state; empty reads "nothing recorded yet"
- **SettingsView**: props `onChange({ key, value })`; `setValues({ quality, fog, exposure, crowd, voice, voiceVolume, details })`. Sections and fields come from [settings-layout.json](views/settings-layout.json) ([schema](views/settings-layout.schema.json)). Look and load: `quality` select (`low`, `medium`, `high`, `ultra`), `fog` range 0..0.003, `exposure` number, `crowd` number. Voices: `voice` select (`on`, `off`), `voiceVolume` range 0..1. Screen: `details` select (`off`, `on`), the developer readouts. Numeric values arrive as numbers.
- **ControlsView**: `setBindings([{action, keys: [string], category?, description?}])`; the studio input reference has local search, host-supplied category tabs, a selected-action guide and a static keyboard highlighting the supplied keys. Refreshes preserve search, category, matching selection, row focus and scroll. It captures no game input and invents no controller mappings. Empty reads "no bindings yet"; a search miss offers Clear filters.
- **BuildingView**: the building viewer overlay; `setStatus(text)` reports preparation and the selected source, `showIssue({ state, title, message, details, exterior })` puts a fatal failure on screen with retry (and return-to-exterior when `exterior` is set), `clearIssue()` removes it, and `setSource`, `setFloorOptions` and `setReport` feed the controls. `setCameraCaptured(captured, failed)` keeps its click-to-capture, Escape-to-release and retry hint aligned with the browser's pointer-lock state. Props `brightness` (default 1) and `onBrightnessChange(multiplier)` drive the live 0.5× to 32× brightness slider, Bright inspection (8×) and Reset light (1×) controls.
- **CityView**: the city-preview overlay; `setWorld(text)` names the loaded world, `setHover(building | null)` reports the parcel under the pointer.
- **ExperimentView**: the scale experiment overlay (props in the file).

## Widgets
- **LibraryCard**: renders one game or city archive row. Game actions report continue/save by game id; city actions report setup/export by city id. Missing handlers create disabled buttons.
- **CreationSteps**: `set(current, unlocked)` marks one of four creation stages current, completed or locked and reports enabled stage selection.
- **TabBar**: props `onSelect( name )`, `onLeave()`; `setActive( name | null )`. Seven entries labelled from the [game menu](views/game-menu.json) ([schema](views/game-menu.schema.json)) in its `tabs` order with their keys: Journal J (the QUESTS panel), Map M, Inventory I, Codex X, Settings O, Controls ?, then Leave. Keys are labels: the game binds them and calls `open`. Panel buttons expose their pressed state.
- **ChatPanel**: props `onSend(text)`, `onClose()`, `onChoice(value)`, `onTopic(value)`, `onAction(id)`, `onRetry()`, `onJournal()`, `onVoice(on)`. `show({ name, role? } | null)` opens a fresh conversation, its talk window closed, or closes the panel. `setNpc`, `setStory({ title, objective?, stake?, hint?, journal? } | null)` (context held in the hint card, closed by default), `setTopics`, `setChoices([{ text, value, disabled?, commits? }], focus?)` (a reply that `commits` carries the mark that it moves the story on, as its accessible description; `focus` puts the first on focus unless the player is typing), `setActions([{ id, label, icon? }])` (each button carries its id as `data-action` and an icon, `icon` or the kind before a colon in the id: `follow`, `lead`, `dismiss`), `setStatus(text, { error?, retry? })`, `setSending`, `setFreeChat(available, note?)`, `setTalkOpen(open)`, `setVoice(on | null)` (the NPC voices setting the composer's toggle shows, pressed while on; null leaves it out), `setTranscript` and `setVisible` expose presentation only; `recall([{ from, name?, text }])` puts what was said with the person before, oldest first, above the conversation's lines, dimmed and tagged earlier. Labels come from [chat-layout.json](widgets/chat-layout.json) ([schema](widgets/chat-layout.schema.json)), `{name}` standing for the person.
  - Lines: `addMessage({ from, name, text, kind? })` appends a whole line and returns its element; `from` is `npc`, `player` (named You) or `scene` (the place and moment a story talk opens on, named Scene and set apart from speech); `kind` `story` or `talk` tags a line of the story or of free talk, as `earlier` tags a recalled line. `beginMessage({ from, name, kind? })` opens a line that grows as it arrives and returns `{ line, update(text), finish(), discard() }`, where `update` shows the text so far; `discard()` removes an unfinished line, and calls on a line that finished, was discarded or left the transcript do nothing. The log is `aria-busy` while a line grows. `setSpeaking(line, 'pending' | 'playing' | 'idle', progress?)` marks how a shown line is voiced; optional `progress()` returns 0..1 of the audio heard to pace the current subtitle. It returns false for a line not in the transcript and throws on another state. A growing line ends in a caret and a voiced line carries a marker; both blink only when the player has no reduced-motion preference.
  - Two surfaces over the running world, neither blurring it. The workflow, along the bottom with the person on the left and the ways to answer on the right: the person's name (the dialog's `#conversation-name` heading) on a chamfered yellow badge, their role on hover/focus and as the heading's description, an optional H hint button, and the newest spoken line as a subtitle (the person's, or the player's after You; a live region while the talk window is closed). Whole NPC lines reveal at the configured characters per second; click the subtitle or focus it and press Space/Enter to complete it. The transcript and accessible subtitle retain the complete text, and reduced motion shows it immediately. Playback progress can pace the reveal without rewinding words already read; voice completion finishes it. Streamed lines update immediately. Scenes stay in the hint card and the transcript. The hint holds the story title, goal, stakes, scene, optional hint text and Open journal; it opens above the badge, scrolls within the desktop viewport, and closes with H or Escape before the conversation can end, the status with Retry, other topics, then one list of the ways to answer: Story replies (numbered, with a small diamond and accessible description for a committing reply; the number keys pick them while the text box is not in use; questions keep the talk going and the marked reply moves the story on), Ask {name} along (the actions, folded while story replies are offered unless the player opened it) and End conversation with its Esc key. Section hints are the groups' descriptions for assistive technology. The button Talk with {name} in the top left corner (key T while the text box is not in use) opens the talk window, or the note saying why free talk is withheld stands in its place. The talk window, closed by default: in the top left corner, a bowed frame with a Free talk plate naming the person (drag it, or move it with the arrow keys; it stays inside the screen and where the player left it), a close that closes the window only, the whole transcript as bubbles (the person's with their initials as a portrait, the player's on the right, scenes set apart), the thinking orb with what it waits for (Thinking while a reply is awaited, Replying while it arrives, Speaking while a voice plays), an Actions tab opening a tray of the same actions with icons beside the window, or over its transcript where the screen has no room beside it, and under the frame a separate bowed composer: the voices toggle, the text box whose placeholder names the person, send. While it is open the workflow centres in the space beside it when that keeps 600 px. The transcript keeps its newest 200 lines. The modal retains keyboard focus when controls are replaced, supports Enter/Space replies and Escape, which closes the hint first, then folds the tray and otherwise ends the conversation, going no further than the chat; it follows the newest text as it arrives or its viewport resizes unless the player is reading earlier text. Pending free chat disables its composer only; authored story choices and actions remain usable. Failures show a persistent explanation, with Retry when the caller offers it, rather than an NPC ellipsis. The conversation palette is one block of `--talk-*` tokens at the top of `chat.css`; while it is open the clock, avatar card, current objective and minimap step aside.
- **SubtitleReveal**: `new SubtitleReveal({ node, owner, charactersPerSecond, onState? })`, `set(text, { animate? })`, `sync(progress)`, `finish()`, `cancel()`. A finite animation frame chain updates at most 30 times per second while text reveals, ends when the owner hides or detaches, and leaves no frame scheduled when complete. `sync` samples an optional 0..1 playback progress callback and never erases words already shown. The owner cancels on conversation replacement and close.
- **ConversationHint**: `new ConversationHint({ anchor?, onJournal? })`, `element`, `trigger`, `panel`, `open`, `unread`. `setStory({ title, objective?, stake?, hint?, journal? } | null)`, `setScene(text)`, `setOpen(bool, { focus?, immediate? })`, `reset()`, `place()`, `dispose()`. The configured sections in the chat layout show only supplied content. New content marks the trigger unread until opened; identical refreshes preserve read state, focus and scroll. No content hides the widget. Opening focuses Close, closing returns focus to the trigger; hidden/closing content is inert. Entry and exit move with finite animations, the unread dot pulses twice, and reduced motion is static. A single finite exit timer and resize observers exist only while needed, cleared on reset/disposal. Removing focused content emits `hintempty` for the host's focus recovery.
- **ThinkingOrb**: `new ThinkingOrb({ size })`, `element`, `setState('idle' | 'thinking' | 'streaming' | 'speaking')`: a small dotted shell with a hollow, in its text colour, hidden while idle and turning otherwise; another state throws. All orbs share one animation frame request, made only while one turns and drawn at most 24 times a second (the browser holds it while the page is hidden); an orb whose element left the page stops. Under reduced motion it stands still. Decorative: its owner says in words what it waits for.
- **LoadingScreen**: the loading surface, small and centred: the Fracture wordmark, a crystal turning in a dial whose arc fills with the load, the game's name under it in the wordmark's fractured bands (`setPlace(name)`, hidden while empty), the percentage in fragmented digits, `done / total work units`, a bar (`progressbar` named Loading progress), four milestones (a list named Loading steps, each `N. label: pending | in progress | complete`, the current one `aria-current="step"`, a ring filling while under way, then a check) and the line naming what loads now (`.hud-loading-step`). `step(text, progress?)` takes the loader's line and its record; the percentage walks the steps and passes of [loading-layout.json](widgets/loading-layout.json) ([schema](widgets/loading-layout.schema.json)) in load order, each with its weight and filled by the whole load's units done since it began, a report naming no listed step counting under the step it runs under; it never goes back and holds at 99 until `ready()`, which fills it and hides the screen. `fail(message)` shows it again, settled, with "could not start" and the reason in `.hud-loading-error`. The load holds the main thread, so everything that moves (crystal, arcs, orbit, digit arrivals, milestone checks, glitches) is a CSS transform or opacity keyframe the compositor plays, and a report writes only what it changed; there are no timers, and a hidden screen runs nothing.
- **AvatarCard** (top left): `setAvatar({ name, role?, portraitUrl?, canvas?, bar })` with bar in 0..1 over 12 segments, `setVisible( bool )`; hidden until the first call. A canvas wins over a portrait URL; when neither is present, the identity and bar remain without an empty portrait frame.
- **VideoCallPanel**: props `onHangUp()`; `setStream( videoOrCanvas )`, `setName( name )`, `setVisible( bool )`
- **MissionToast**: `show({title,text})` slides into the studio notice stack below the clock, holds and removes itself (about 4.4 s). At most two notices and their timers exist; each has a dismiss button and status semantics. `destroy()` clears timers and removes the stack.
- **CurrentObjective**: `setObjective({ title, objective, state: 'active' | 'done', place } | null)`; an active or completed objective stays quietly visible and opens QUESTS when activated, while null hides and clears it. `place: { name, distanceMeters?, window? }` adds the venue line under the objective text, with the walk in metres while a route stands, and an "Opens <label>, HH:MM to HH:MM" line while the place's `window` is given
- **MissionSummary**: the story card. Props `onClose({ pointer })`, `onOpen()`; `show({ kind: 'outcome' | 'prologue', title, text, outcome: 'done' | 'failed', steps: [{ text, done }] })`, `setVisible( bool )`; it opens as a named modal focused on its action, retains focus after text clicks, and the action or close button reports `{ pointer: true }`, Escape `{ pointer: false }`. `outcome` (the default, and any kind the layout lacks) shows the outcome badge and continue; `prologue` shows the Prologue line and Begin. A blank line in `text` starts a paragraph. Labels come from [summary-layout.json](widgets/summary-layout.json), [schema](widgets/summary-layout.schema.json). GameView hides it before forwarding `onSummaryClose(close)`; the host releases pointer lock on open and takes it back on a click close, while Escape leaves the pointer free where the game stood.
- **HudClock**: `update(time, district, location?)`, `setState('dawn' | 'day' | 'dusk' | 'night')`; the studio time/location stack at top left separates a supplied weekday from HH:MM and shows the actual named venue when available. Unchanged text is not rewritten.
- **HudShortcuts**: quiet E/J/M/? binding references at bottom left; the dock owns navigation.
- **InspectionCard**: `show({title,text})`, `setVisible(bool)`; a named reading dialog for accepted document/evidence results, with paragraphs, trapped focus, Escape and Return to the city. `onOpen()` releases the pointer; `onClose({pointer})` follows the story card convention. It owns no quest state.`
- **InteractPrompt**: `update(text | null)` preserves the complete owner-supplied prompt, draws E/R and lift key labels as keycaps and shows the studio target reticle only while a target exists; repeated text does not rebuild nodes.
- **LocationReadout**: `update( position, district, parcel )`, `setAbout( paths )`
- **DebugStats**: `update( stats )` with `{ backend, tier, width, height, frameMs, gpuMs, drawCalls, triangles, lights, crowd, cars, interiors, materials, unresolved, hitches, worstMs }`; the first row names the backend, the tier and the render size, warned on the fallback backend; `gpuMs` null reads `gpu n/a`, a backend without GPU queries; then how many material keys resolved, warned while any has not, and last whether the run has stalled and by how long, warned once it has
- **PauseMenu**: props `onResume()`, `onOpen( name )`, `onSave()`, `onLeave()`. The Fracture wordmark over the title, then the `pause` sections of the [game menu](views/game-menu.json): each entry a button with a line saying what it does and its key, then the keys to play with; a click beside the menu resumes. `setVisible( bool )` focuses Resume as it opens and forgets how the last save went. `setSave( 'ready' | 'saving' | 'saved' | 'failed' | 'unavailable' )` sets the Save entry's line, disabled while saving and for a game that is not saved; another state throws.
- **TransitHud**: props `onSelect(value)`, `onCancel()`; `choose([{ id, label, value, code?, detail? }], mode = 'service')` opens an accessible dialog with one focused button per candidate. Mode `destination` uses the destination title from [layout](widgets/transit-layout.json); [input schema](widgets/transit-hud.schema.json). The studio choice list shows the supplied service code and detail. Arrow keys, Home/End and trapped Tab move focus, Enter selects, and Escape or cancel reports cancellation without passing Escape to the game. Empty lists focus Cancel. `close()` removes it, `open` reports its state, and `ride(text | null)` shows or clears the studio journey strip with the current line and next stop; unchanged text does not rewrite its nodes.

## Components
`dom.el`, `Icon.icon( name )`, `FractureLogo.fractureLogo({ label = 'urbe', glitch = true, backed = false })` (the Fracture wordmark: URBE cut into three shifted bands with a soft double of the middle one; six thin cuts jump sideways in a 6.4 s cycle unless `glitch` is false, over the screen's colour `--fracture-backing` when `backed`; one image named `label`, every movement a compositor transform or opacity step, still under reduced motion or `.is-still`), `KeyCap.keyCap( text )`, `PanelHeader` (title, key hint, Esc button), `EmptyState.emptyState( text )`, `Prose.prose( text )` (story text as paragraphs for a `prose` container), `SettingField`, `Button`, `SelectField`, `MenuButton.menuButton` (label, detail line, optional key). Stylesheets: `game.css` (palette and HUD chrome), `fracture.css` (the wordmark), `loading.css` (the loading screen), `tabbar.css`, `panels.css`, `views.css`, `chat.css`, `mission.css`, `launcher.css` (front door and creation stages), `styles.css` (viewer and experiment overlays).

## Invariants
- Presentation only: nothing here reads game state or touches the scene. The game overlay (GameView and everything it mounts) imports nothing from outside `src/ui`; ExperimentView alone reads the scale experiment's option lists.
- Every component uses square corners, but for the conversation's talk window, its composer, the button that opens it and its bubbles, which are bowed as the chosen design draws them.
- The tab bar always shows each panel's key and is only on screen while a panel is open; the pause menu lists the same panels, a line each.
- One full panel at a time; Escape closes it.
- Maps redraw on pan, zoom, turn or data change, never per frame on their own.
- At narrow viewport widths, the front door compacts its navigation, the tab bar keeps all seven actions visible, and dialogs and panels remain inside the viewport.
- A city is a generated world artifact. A game is the final city plus its selected interiors, quests and playthrough. The UI never presents these as the same directory.
- Creation order is enforced in the UI: city, interiors, story and side jobs, playable game.

## Tests and preview
`*.test.js` beside each view and widget, Testing Library plus user-event on jsdom (`// @vitest-environment jsdom`), one per declared input, output and event. `test-helpers/canvas.js` gives jsdom a recording 2d context.
`preview.html` shows the whole overlay with sample data and no game behind it, starting on the game directory: `npm run dev`, then `/src/ui/preview.html`; `?chat` opens on the conversation, `?talk` with its talk window open, `?paused` on the pause menu, `?prologue` on the story card.

## Depends on
Nothing outside this folder. The game (`src/game/CONTRACT.md`) is the caller.

Objective map marks use muted blue-grey: a 6 px diamond on the minimap and a 0.9 m octahedron at 1.6 m height on the city map. Lift prompts expose Page Up and Page Down selection and E confirmation.
