# CONTRACT: assembly (engine inner box)

Purpose: turns the atlas blueprint plus the connections document into per-parcel exterior BuildingRequests, drives exterior to produce each building's GLB and blueprint, and optionally drives interior to fill the shell.

## In
- atlas blueprint: `CityBlueprint` per ../../../atlas/CONTRACT.md; single-building and simulation CLIs take `--blueprint <path>` as ordinary JSON or a [World Archive](../world-archive/CONTRACT.md) directory or `index.json`, and defaults to the committed sample `../../../atlas/samples/city-urbe.json` (assemble-city requires it explicitly). A named world per ../../../naming/CONTRACT.md (the same blueprint with `name` on its nameables and `meta.naming`) is taken through the same flag: parcel names become sign text, district names are not read.
- connections document: `ConnectionsOutput` per ../../../connections/CONTRACT.md, produced in-process by `connectionsRunner.js` calling the library entry `generate(atlas, { seed })` with the atlas seed. A city batch generates it twice. The first pass, on the Atlas envelopes, gives every request its apertures. The pass the world keeps runs once the plans are drawn, against the buildings that stand (`StandingBuildings.js`): each kit parcel's `footprint` is the ring its shared building stands on (its plan's massing in the parcel's frame, the same winding, covering both lots where a merge joined them) and `params.buildings` carries that building's own roof elevation; a lot with nothing on it is reported as not standing; a landmark, a parcel the generator still owes and a parcel that fell back to it keep their Atlas massing and envelope. So a link end is cut on the facade that stands, not on the lot Atlas drew. A reuse run reads the same rings and roofs off the buildings already on disk.
- rooftop fitting runs after every shell. `RooftopSpanPlan` takes each finished Exterior blueprint's nested mast `externalAttachments`, plus closed building, roof-access and non-mast equipment prisms, and calls Connections `generateRooftopSpans(request)`. The complete scene comes from the blueprints that stand, a kit parcel's composed into its own frame ([kit](kit/CONTRACT.md)), so every endpoint sits over the building that offers it; assembly adds no endpoint or obstacle geometry.

## Out
`RequestAssembler(atlas, connections).assemble(parcelId, { glb })` returns a `BuildingRequest` per ../../../exterior/schemas/building-request.schema.json:
- seed: `<atlas seed>:<parcelId>`
- parcel: footprint, access point and nominal maxHeight from the Atlas parcel, verbatim. `parcel.streetAccess { edgeId, path }` carries the exact named access edge and its complete source path from `atlas.streets.edges`; the original access point remains unchanged. Missing access edges fail with `E_REQUEST_INVALID`. When Atlas publishes `meta.buildingGrid`, `parcel.buildingGrid` carries its origin, angle and spacing unchanged to Exterior; older worlds omit it.
- building: atlas type and tier verbatim; floors seeded inside the intersection of the atlas envelope and exterior's feasible range, computed with the recipe and generationPolicy in ../../../exterior/schemas/floor-constants.json (`floorFeasibility.js`). The active minimum is max(family minimum, defaultClearHeight + clearHeightAllowance), currently 4.5 m; taller family minima remain taller. Floor-count integer division accounts only for the floating-point error bound of its operands and arithmetic; source coordinates remain unchanged. Fixed above-ground and basement bases retain exact gaps, and incompatible gaps fail E_ENVELOPE_INFEASIBLE. Basement counts satisfy the same active bound; wire anchors pin no floor plate
- theme: `cyberpunk`
- apertures: the connections apertures whose buildingId equals the parcel id, verbatim
- options.architecture: an approved family for a landmark whose own footprint, floor count and street take one, the landmark design `garden-taper` first, then `corporate-sectors`, then a seeded pick of the rest, and never `garden-taper` when a connection cut above ground pins the faces. Every other parcel is `auto`, where Exterior selects its accepted architecture and native finishes while retaining fixed aperture/anchor faces.
- options.doorMotion is omitted for automatic architecture, so the selected Exterior recipe owns door motion. Explicit door-motion constraints supplied to Exterior remain hard constraints.
- options.glb: `merged` (engine runtime default) or `named`
- options.signage: a `marquee` for the parcel types a passer-by reads off the street (hotel, coffee_shop, commerce, clinic, police, restaurant); every other type gets none, because a blank sign is worse than no sign. The text is the parcel's `name` lettered for exterior's atlas (`signText.js`): diacritics folded onto their base letter, uppercased, any character still outside the charset in ../../../exterior/CONTRACT.md read as the space it reserves (runs collapsed), then whole words in order while they fit the marquee limit exterior's request schema sets (40 characters). A parcel with no name, an empty one, or one whose first word alone passes the limit reads its venue word instead (hotel HOTEL, coffee_shop COFFEE, commerce MARKET, clinic CLINIC, police POLICE, restaurant DINER). `assemble(parcelId, { signage })` picks the rung: `name` (default), `venue` (the word), `none`.

`assembleInterior(parcelId, { blueprint, shellGlb })` returns an `InteriorRequest` per ../../../interior/schemas/request.schema.json: same derived seed, building id/type/tier verbatim, the exterior blueprint, materialTheme `cyberpunk`, and `shellGlb` only when the parcel has a GLB of its own (a kit building has none); assignments omitted so interior derives floor kinds from the blueprint slots. `interiorRunner.js` calls interior's library entries as black boxes: `coreFeasibility(blueprint)` gates generation (footprint-shape driven, per ../../../interior/schemas/core-feasibility.json; modes standard, compact, walkup, none), then `generate(request)`, `writePlacements(result, dir)` and `expandBuilding(result)`. Standard and compact flow straight through. When the gate reports walkup mode and the chosen floors exceed its cap, a generated shell re-picks floors with `assemble(parcelId, { floorCap })` (the cap wins over the atlas envelope minimum, aperture-driven minimums stay hard) and is regenerated before running interior; a kit building keeps its pieces, so it is furnished as it stands or stays closed. Mode none fails as E_CORE_INFEASIBLE.

The per-parcel chain lives in `BuildingPipeline.js` (assemble + validate, exterior CLI, core gate with walkup re-pick, interior files) and is shared by both CLIs; `furnish(parcelId, outDir, { blueprint, refit })` fills a building that already stands, from the blueprint both paths publish. A facade the sign text does not fit on throws `E_SIGNAGE_TEXT_TOO_LONG`; the building steps down one rung (name, venue word, no sign) and is regenerated rather than failing the parcel. `merged` is the runtime GLB default everywhere.

CLI: `npm run assemble -- --parcel <id> --out <dir> [--blueprint <path>] [--glb merged|named] [--interior]` validates each request against its schema (ajv, draft 2020-12), writes `<id>.request.json` to `<dir>`, then runs exterior's CLI (`npm run generate` in ../../../exterior) so `<dir>` ends with request, GLB and blueprint. With `--interior` it also writes `<dir>/interior/`: `building.json` (interior's own index: the three layouts it names, every floor's index, elevation and opening map, and the connectors), `layouts/ground.json`, `layouts/middle.json` and `layouts/crown.json` as interior writes them, and `npc.json`, the `expandBuilding` result with the building's real per-floor identities. A furnished building is JSON alone; its geometry is the shared modules and furniture the city publishes once. Prints each output file with its size.

Exterior request validation loads its published local schema dependencies unchanged, including blueprint policy, facade-service and mast-attachment definitions. File-relative references are registered under their resolved schema IDs; validation performs no network reads.

City batch: `npm run assemble-city -- --blueprint <path> --out <dir> [--workers N] [--interiors N] [--parcel <id,id,...>] [--reuse-shells true] [--interior-parcels <id,id,...> | --interior-priority <id,id,...>]` builds every parcel's blueprint and the geometry that draws it, and plans the links it keeps over the buildings that came out. Ordinary parcels take the [kit path](kit/CONTRACT.md): each distinct building is generated once by the workers into the shared store and every parcel of it ships `<id>.placements.json` alone, which names that plan and the frame it stands in; the plan carries the shell and the blueprint every parcel of it composes its own from. Blocks Atlas tiled from a `meta.blockTemplates` entry are dressed by the template, so the city repeats a handful of block designs with one variation each, and a variation that merges two lots leaves the second one empty while the building that covers it stands. Landmarks and parcels no shared building fits are generated on their own lot by the workers, N in parallel. The plans are drawn first, so no parcel is written before the building it stands from has a shell in the store. A parcel folder holds one building: taking the kit path drops the GLB and request of a shell that stood there, and going back to the generator drops the placement record. N defaults to a quarter of the machine's available parallelism, `URBE_ASSEMBLY_WORKERS` overrides that default, and a batch never opens more workers than it has parcels to build. A temperature ceiling is on by default and `URBE_ASSEMBLY_MAX_TEMP` overrides it, 0 disabling it. It follows the die, `k10temp` or `coretemp`, and reads the `acpitz` chassis probe only where neither exists, because that probe answers about case airflow rather than about how hard the cores are working. It is 90 C, the temperature this project asks a batch to hold under, dropped to three degrees below the throttle point on a machine whose driver publishes one lower than that (`tempN_crit`, else `tempN_max`); it is never raised to meet the hardware. A desktop CPU boosts until it meets its own limit, so the die sits wherever the boost algorithm parks it, which on this machine is 95 to 98 C, and a batch there narrows towards its floor and stays: that is the ceiling holding, not failing, and the worker cap stays a quarter of the cores whatever it does. The pool samples every two seconds and decides on the middle of the last three readings, so a sensor spiking for one boosted core changes nothing; a sustained reading above the ceiling dispatches one worker fewer, down to two and never to a serial build, and it widens again once the die has cooled four degrees below. The run's final report states how often it narrowed. The worker cap stays the first heat control. `--reuse-shells true` makes the command require and retain every existing shell instead, so a generated city can become a game without rebuilding its geometry; it cannot be combined with `--parcel`. It furnishes five buildings by default. Any standing building can open, from its pieces or from its own GLB: a building is furnished from its own blueprint, its folder's for a generated shell and its plan's for a kit parcel, so a kit parcel picked to open keeps its placement record and stays reported as `kit`; a plan Interior cannot furnish leaves that building standing and closed. Interior fills a ground, a middle and a crown layout, and a two-floor building opens with ground and crown alone. `--interior-parcels` supplies the exact unique subset for a manual build and makes its length the target; an id outside the blueprint, in either list, ends the run before any work is done (`E_INTERIOR_SELECTION`, exit 1), and a named parcel that ends with no building is listed in the report's interior failures while the rest of the selection opens. Otherwise `--interior-priority` parcels, which order an automatic pick and cannot be combined with `--interior-parcels`, rank first in the order given, then parcels explicitly referenced anywhere in carried `<out>/quests/questlines.json`, in the order the questlines name them (the main line before its side jobs); remaining slots come from commerce, mall, restaurant, coffee shop, hotel, clinic, hospital and police parcels by a stable hash of the atlas seed and parcel id, never input order. A candidate whose interior fails keeps its complete shell closed and the next candidate is tried.

A city never fails because one parcel failed. A parcel whose kit plan or generator throws ships nothing and is published as the empty lot it is: `source: "empty"` in the manifest, and a `qa-report.json` entry carrying the error and the lot size, type, tier and floor allowance it was going to have. A lot a block's variation merged into its neighbour is empty the same way, but only while that neighbour stands: a host whose own building failed leaves the lot its own generated shell, so one failure never costs two lots. The batch carries on and exits 0 whenever the manifest was published; the report lists every empty lot, and separates shell failures from interior failures. Malformed CLI options exit 2.

`<dir>/qa-report.json` holds `totals` (parcels, passed, failed, kit, generated, empty, plans, interiors, wall time, bytes), the `plans` the city uses, one record per parcel and the interior failures. A kit parcel's record carries its `template`, `slot` and `plan` beside its `source`.

The out dir contains exactly the blueprint it was built from (`OutDir.js`). Parcel folders absent from that blueprint are removed before the run, and only folders carrying an assembly request or blueprint are touched. The city CLI requires ordinary JSON and publishes `<dir>/blueprint.json`, and `<dir>/npc-types.json` is the naming box's typed set found beside it, so the folder is the whole world the game loads; `<dir>/manifest.json` conforms to [schema/world-manifest.schema.json](schema/world-manifest.schema.json) and is written last:

```
{
  "contractVersion": "1.0.0", "seed": "urbe-tiny", "atlasVersion": "0.2.4",
  "named": true, "namingTheme": "rain-soaked port city",
  "parcels": [ "p0", "p1", ... ],
  "interiors": [ "p1", ... ],
  "floors": { "p1": [ "000", "001", "002" ], ... },
  "kit": { "file": "kit.json", "sha256": "<64 lowercase hex characters>", "shared": "kit/<16 hex characters>" },
  "interiorModules": { "file": "modules.json", "sha256": "<64 lowercase hex characters>", "shared": "interior-modules/<16 hex characters>" },
  "interiorProps": { "file": "catalog.json", "sha256": "<64 lowercase hex characters>", "shared": "interior-modules/<16 hex characters>" },
  "sources": { "p0": "shell", "p1": "kit", "p2": "empty", ... },
  "buildings": { "p1": { "template": "bt-downtown-105.8x105.8", "slot": 2, "plan": "white-grid-offices-rich-5x7x9f" }, ... },
  "connections": { "file": "connections.json", "sha256": "<64 lowercase hex characters>", "blueprintSha256": "<64 lowercase hex characters>" },
  "rooftopSpans": { "meta": { "seed": "urbe-tiny:rooftop-spans", "schemaVersion": "1.0.0", "generatorVersion": "0.10.0" }, "spans": [] }
}
```

`kit` is present when any parcel stands from a shared building and binds the world's plan index in the shared store; `sources` says how each parcel is drawn, `kit` for a placement record, `shell` for its own GLB and `empty` for a lot the city deliberately has no building on, which is named here and in no other list. `buildings` names, for each kit parcel, the Atlas block template and lot slot that dressed it and the plan it is a copy of, whose blueprint is what its own is composed from. `interiorModules` and `interiorProps` are present when any building is furnished and bind the two catalogs `interior/building.json` names, published once into the shared store (`InteriorModules.js`), which is the resource base that file resolves them against. `interiorModules` binds `modules.json` and the room GLBs beside it, built through interior's `buildModules()` at publish time so the set is always the one the interior that furnished the buildings draws with (`URBE_INTERIOR_MODULES_DIR` names a prebuilt set to publish instead). `interiorProps` binds `catalog.json`, interior's furniture catalog, published with every model its `modelUri` names under `models/` (`URBE_INTERIOR_PROPS_DIR` overrides the sibling `interior/src/assets`). A `local-only` entry whose model the machine does not hold leaves the published catalog, and one warning lists those ids; any other missing model fails as `E_INTERIOR_FAILED`. `named` says whether the blueprint's parcels carry names, and `namingTheme` is `meta.naming.theme` when the blueprint records one, else null. `parcels` is every id with a complete exterior blueprint and the geometry to draw it: its own GLB, or its kit placement record. An empty lot is not one of them, so the game never fetches anything for it. `interiors` is the subset carrying `interior/building.json`, the three layouts it names and `interior/npc.json`; `floors` has exactly those ids and lists their floor tags lowest first, read off `building.json` (zero-padded index, `000`); a furnished building starts at floor zero, so its tags are never negative. `rooftopSpans` is Connections' validated schema 1.0.0 output and may be empty. Older manifest 1.0.0 documents without that additive field load as an empty span set. A shell that is deliberately closed remains in `parcels` and is not a failure. This is the only list of buildings, floors and rooftop spans the game loads: a directory listing would pick up stale output, and the seed and version let the game refuse an out dir assembled from a different blueprint outright.

Shared resources: the building plans, the street kit, and the interior modules with their furniture catalog and models are the same bytes for every city built from the same boxes, and the furniture alone is 64 MB. Each set is published once under the hash of what it holds, at `engine/out/shared/<kind>/<first 16 hex of its sha256>/` (`SharedResources.js`, `URBE_SHARED_DIR` moves the store), and a world's manifest names it with `shared` beside `file` and `sha256` instead of carrying a copy. The runtime resolves such a reference against `/out/shared` (`WorldSource.js`), so a hundred cities on one machine read one copy and a world folder holds only what is its own: its parcels, its plans, its street placements and its documents. A set nothing points at is a folder to delete. `collect(root)` deletes exactly those: it reads every manifest under the worlds root (`engine/out` by default, at any depth), keeps the sets they name plus the plan sets their kit index names, removes every other set and nothing outside the store, and returns `{ removed, kept }`, each the set paths and what they weigh in bytes. `npm run gc` runs one sweep and prints the totals. A city batch never sweeps: two batches drawing plans at the same time would otherwise remove each other's sets before a manifest points at them, so the sweep is a separate step run when no batch is drawing (the coordinator's matrix gate runs it last).

Every city batch persists the unchanged [Connections output](../../../connections/schemas/output.schema.json) from its single base generation. `ConnectionsArtifact(atlas, connections)` checks that schema and matching source seeds, then captures an immutable Connections snapshot and canonical JSON-plus-LF hashes through World Archive's bounded byte iterator. `OutDir.writeManifest(atlas, parcelIds, interiorIds, rooftopSpans?, connectionsArtifact?)` synchronously publishes ordinary `blueprint.json` and `connections.json` with the existing bytes and manifest shape. Its Connections reference hashes both complete files, including LF. No whole-document JSON string is allocated.

For archive input, `await OutDir.writeArchiveManifest(atlas, parcelIds, interiorIds, rooftopSpans?, connectionsArtifact?, options?)` writes both documents through World Archive; options follow its [write schema](../world-archive/schema/api.d.ts). The additive manifest references are `blueprint: {file:"blueprint/index.json", encoding:"archive", sha256}` and `connections: {file:"connections/index.json", encoding:"archive", sha256, blueprintSha256}`. These digests cover exact index bytes; `blueprintSha256` equals the blueprint reference hash. The blueprint index's original-content binding must match the Atlas hash captured at Connections generation. Both archives prepare before publication; failed replacement restores the prior archives. The complete manifest shape is shared by both encodings and follows [schema/world-manifest.schema.json](schema/world-manifest.schema.json). Blueprint, Connections, QA and carried NPC types precede atomic final-manifest publication.

Manifest 1.0.0 without `connections` remains readable through the game's existing generation path; omitting the optional artifact in `writeManifest` preserves that shape. A declared reference requires its file, valid JSON and Connections schema, matching source seeds and both byte hashes. Missing, invalid or source-mismatched declared data fails world loading and never regenerates.

Tapered floor bands retain optional `topOutline` vertices in the shell catalog; adjacent sloping bands remain separate.

Shell streaming: the city CLI reads one completed Exterior blueprint at a time. `ShellArtifacts.js` exports `collectShellArtifacts(directory, parcelIds, {seed})`, which returns a [shell catalog](schema/shell-catalog.schema.json) and the projected Connections rooftop request; full blueprints and openings are released after each record. The catalog retains actual nonnegative floor count, basement count, Exterior massing bounds, a ground-plane center, consecutive identical floor-outline/material bands, and exact roof outline, elevation and parapet height. Band materials come from `facade.materialPlan.field`, with an authored `groundMaterial` on floor zero. Roof material comes from explicit `roof.material`, verified against the published material/variant tables. Older stored blueprints use their unique roof-family key and named variant; the parapet proxy keeps the material-plan concrete field. No Atlas representative height enters the catalog.

`await OutDir.publishManifest(atlas, parcelIds, interiorIds, {rooftopSpans, connectionsArtifact, catalog, encoding, archiveOptions, streets})` prepares source documents plus the catalog, then publishes one final manifest. `encoding` defaults to `json`; archive options follow World Archive. The additive reference `shellCatalog: {file:"shells/index.json", encoding:"archive", sha256}` hashes exact index bytes. Catalog IDs must equal manifest shell IDs and its seed must equal Atlas. A generated shell's full `${id}/${id}.blueprint.json` and `${id}/${id}.glb` remain available for proximity loading; a kit parcel's blueprint is composed from its plan. Legacy manifests may omit the catalog.

Native streets: city batches set `streets:true` on `OutDir.publishManifest`. `WorldFiles` first writes the final staged blueprint.json, then `buildStreetArtifacts(stage,atlas,options)` calls the Streets public build with that exact file path. Streets read the blueprint alone, so `new StreetsAhead(outDir, atlas, options)` runs that build in a worker while the shells build, and `prepared()` returns its directory and reference. Passing it as `streetsPrepared` publishes that bundle instead of building again; it is adopted only when its reference binds the staged blueprint bytes and the built manifest and kit bytes, and fails with `E_STREETS_SOURCE_MISMATCH` otherwise. The bundle is prepared in staged `streets/`; its input file hash/version and the unchanged staged blueprint bytes must agree. That directory carries the Streets bundle: `manifest.json` (Streets manifest 0.5.0 with `kit` 1.2.0, `placements` 1.2.0, `files`, `ground`, `report`, `features`, `materials`, `closures`, `delegated` and `statistics`), `kit.json`, `placements.json` and `pieces/**`, so the `streets/kit.json` and `streets/placements.json` paths the manifest names resolve from the world root and each kit piece file resolves beside the kit. A placement names one published piece, its world position, its rotation, its optional scale and the shader values it draws with: `tint`, `wear`, `scan` and `text`. The catalogue is one shared 187 piece kit, identical for every city of this design, so every world names one folder of the shared store and the store holds one entry; only the placements differ from city to city. Publication moves the bundle with the source documents and rolls back replacements on failure. The additive manifest reference is `streets:{file:"streets/manifest.json",sha256,kitSha256,blueprintSha256,sharedKit}`; every digest hashes exact published bytes, and `sharedKit` is where `kit.json` and `pieces/**` stand in the shared store, which is what the runtime resolves piece files against. The world keeps `streets/manifest.json` and `streets/placements.json`, which are its own. Streets' native manifest, kit and piece hashes remain unchanged.

Library `streets` defaults to false for stored-world publication compatibility; true uses the published native Materials binding, a seed derived by FNV-1a of `<atlas seed>:streets`, and wear 1. [Street options](schema/street-options.d.ts) may supply seed, wear or a native binding object/path. Normal city generation always enables native streets. Archive plus native publication fails before staging/publication; the city CLI rejects archive input before producer work. Existing manifests without streets remain readable. Native generation requires a saved Atlas 0.26.0 blueprint JSON with planning reservations 2.1.0, with no version downgrade.

Simulation: `simulationRunner.js` calls simulation's `createSimulation(input)` as a black box. `npm run simulate -- --time <minutes> [--district <id>] [--blueprint <path>] [--interiors <dir>]` boots it over the blueprint, connections' networks and the npc.json of every assembled building under the interiors dir (default `out/`) (synthetic fallback elsewhere, default npcTypes and name pool), prints population stats, the scoped crowd slice, three instantiated lives (a sampled crowd agent's handle, coffee vendor at midday, a reservation), latency measurements and a conservation check; usage error exit 2, no live crowd agent exit 1.

Interior resource identities hash both catalogs and every model's bytes, including
edits that leave the catalog and model sizes unchanged. Re-publishing an existing
content identity repairs missing or corrupted files through individual atomic file
replacements; a prebuilt module catalog naming absent geometry fails before publish.
Shared-store garbage collection also retains standalone `preview.json` records'
`interiorModules` and `interiorProps` references, including legacy preview metadata;
removing a preview makes resources used only by that preview eligible for collection.

## Errors
- `E_STREETS_ARCHIVE_UNSUPPORTED`: native generation requires ordinary blueprint JSON
- `E_STREETS_BUILD`: the Streets public build failed; its source error code/message is retained
- `E_STREETS_SOURCE_MISMATCH`: native identity differs from the exact staged blueprint bytes or version
- `E_CONNECTIONS_INVALID`: generated Connections fails its published output schema (thrown as `AssemblyError`; CLI exit 1 before shell work)
- `E_CONNECTIONS_SOURCE_MISMATCH`: Connections source seeds differ from Atlas, an input archive's original-content binding is false, or Atlas bytes changed after artifact capture (thrown as `AssemblyError`; CLI exit 1 without publishing a new manifest)
- `E_KIT_MANIFEST`, `E_KIT_FIT`, `E_KIT_PLACEMENTS`: the kit path's own failures, per [its contract](kit/CONTRACT.md). A kit that fails its schema ends the run, and a machine that publishes none sends every parcel to the generator; a parcel that fails to place is published as an empty lot and reported
- `E_PARCEL_UNKNOWN`: parcel id not in the atlas blueprint (thrown as `AssemblyError`; CLI exit 1)
- `E_ENVELOPE_INFEASIBLE`: no floor count satisfies both the atlas envelope and exterior's feasibility recipe for the parcel's apertures (thrown as `AssemblyError`; CLI exit 1)
- `E_REQUEST_INVALID`: an archive input has no fixed `index.json` name, a parcel's named access street is absent, or its assembled request fails the Exterior schema (CLI exit 1, schema errors printed)
- `E_EXTERIOR_FAILED`: exterior CLI exited nonzero (CLI exit 1, its output printed)
- `E_CORE_INFEASIBLE`: interior's coreFeasibility gate reports mode none, the footprint cannot hold any core (CLI exit 1; mode, band and core lengths printed)
- `E_INTERIOR_FAILED`: interior's generate threw, or the shared module and furniture sets could not be published into the shared store (the building stays closed and is listed in the report's interior failures)
- `E_SHELL_CATALOG`: an Exterior shell lacks valid massing or published material bindings, or its catalog seed and IDs differ from the manifest (CLI exit 1)
- `E_ARCHIVE_*`: World Archive input, part, hash or publication failure, passed through its public contract (CLI exit 1)
- usage error: CLI exit 2. Every other case exits 0 once the manifest is published, however many lots stand empty

## Invariants
- Deterministic: same atlas and connections inputs, byte-identical request JSON.
- Apertures are passed through untouched; assembly never edits connections geometry.
- After a city batch the out dir holds a folder for no parcel outside the blueprint. `manifest.json` lists all complete shells, lists complete interiors as a subset, has floor files for exactly that subset, and carries exactly the rooftop span document generated from those shell blueprints.
- A city batch persists one Connections document, the pass it ran over the standing buildings; its artifact retains that document and binds the complete published Atlas content, the blueprint as Atlas wrote it. Invalid artifact input or an output write failure cannot publish a new manifest.
- A furnished building names only modules the shared `modules.json` holds, so the world draws it from the sets the manifest binds. Its furniture ids come from Interior's full catalog; one the published `catalog.json` lacks is a local-only model this machine does not hold.
- The CLI needs a TS-capable loader for the connections and interior entries; the npm script runs it under tsx.

## Depends on

`PlanLibrary` and `KitAssembler` ([kit](kit/CONTRACT.md)) own the kit path: which parcels a shared building can stand on, which family each wears, the placement records, and the plans themselves in the shared store, which the manifest binds by hash. The city CLI asks `candidate(parcelId)` before it queues anything, so a parcel the kit cannot take is generated instead and reported as such in `qa-report.json`, where every parcel carries `source: "kit" | "shell" | "empty"`.

City batches use `ExteriorWorkers(count)` to reuse producer workers through the [worker port](schema/exterior-workers.d.ts). `run(request, outDir)` takes Exterior's [BuildingRequest](../../../exterior/schemas/building-request.schema.json), writes its original keys-only GLB and [blueprint](../../../exterior/schemas/blueprint.schema.json), and returns the blueprint. `close()` releases workers and rejects unfinished jobs. `BuildingPipeline(assembler, {exterior})` accepts this port; single-building calls retain their CLI path. Producer validation and generation errors remain `E_EXTERIOR_FAILED`.
